# Project Mentor — Brainstorm to Build Anything

**Honest, one-question-at-a-time design mentor that turns a rough idea into an approved, agent-ready project log and inheritance document.**

Project Mentor helps you move from a vague idea (or partial work) to a clear, finishable specification. It asks one high-leverage question at a time, surfaces contradictions and gaps with recommended fixes, and locks nothing in until you explicitly approve it. The result is a structured project log plus an inheritance document that any later AI or human can pick up without guessing.

It works for software, systems, businesses, skills, books, products, research, events, and more. When the project is itself an AI skill or prompt, it can also help turn the approved log into a tested skill ready to publish.

---

## Purpose

Most project conversations drift, leave gaps, or quietly assume things that later cause rework. Project Mentor exists to keep the process honest and progressive:

- Start from Purpose and a clear success criterion.
- Build a Spine of key layers (scope, flow, risks, validation, delivery, etc.) and Modules that slice the work.
- Use forward charts for the main path and a reverse flowchart that starts from the goal and stops at the first missing prerequisite.
- Keep every item marked Open, Approved, Parked, or N/A so the authoritative state is always clear.
- Produce an inheritance document and optional packages only when you are ready.

The north star is a log and hand-off document that an implementing agent can follow without inventing missing pieces.

## Core Abilities

| Ability | What it does |
|---------|--------------|
| **One-question cadence** | Asks the single highest-leverage question (with a recommended answer or options) and waits. Avoids overwhelming you. |
| **Approval discipline** | Nothing becomes binding until you explicitly approve it. Suggestions, research, and grades stay provisional. |
| **Pushback protocol** | Surfaces unrealistic scope, contradictions, or risks plainly, explains why it matters, and recommends a fix or options. You decide; accepted risks are recorded. |
| **Spine + Modules** | Organizes work into tagged layers and vertical modules so pieces can be handed to agents cleanly. |
| **Forward & reverse charts** | Forward flow from first action to goal; reverse chart from goal backward, stopping at the first open or parked gap. |
| **Status markers** | Every item carries Open / Approved / Parked / N/A so readers know what is authoritative. |
| **Audit** | Checklist for contradictions, blocking gaps, reverse-chart gaps, real-world conflicts, and severity items. |
| **Package & inheritance** | Builds a bundle with the inheritance document, log (with decision history), and manifest. Asks before including extra materials. |
| **Skill builder path** | When the project is a skill or prompt, can turn the approved log into a tested skill and help plan publishing. |
| **Lite mode** | Collapses structure for small efforts while still enforcing approvals and status. |

## Why Use Project Mentor

- **Honest feedback** — Design success outranks comfort; gaps and risks are named with recommended fixes.
- **You stay in control** — Explicit approval is required before anything is locked in.
- **Progressive clarity** — One high-leverage question at a time keeps momentum without overload.
- **Agent-ready output** — The inheritance document and log are written so a later AI (or human) can continue without guessing.
- **Works for many project types** — Software, systems, businesses, skills, books, products, research, and more.
- **Reverse view of gaps** — The reverse flowchart shows the next missing prerequisite instead of only the forward path.
- **Optional skill publishing** — Special support when you are designing a reusable AI skill.

It is especially useful when an idea feels fuzzy, a plan has hidden assumptions, or you need a clean hand-off for implementation.

## How to Install and Use with AI

### Quick Install
1. Open [`SKILL.md`](SKILL.md).
2. Copy the **entire** file.
3. Paste it into your AI as a system prompt, custom instructions, project knowledge, or skill upload.

### Activation Notes
- Loading the file does not force every response into mentor mode.
- Start by saying something like “Mentor me on this project,” “help me think this through,” or “what am I missing?”
- The skill will check whether this is a fresh idea or existing material, then begin with Purpose and success criteria (or anchor from what you already have).
- Answer one question at a time. Approve items you want locked in; park or leave open anything you are not ready to decide.
- When the work is finishable (no blocking open items, or you accept the remaining risks), ask for an audit or package.

### Practical Tips
- Share any existing notes, links, or partial work early so the skill can anchor rather than restart.
- Use natural language; exact commands are optional (“show approved,” “audit,” “package,” “grade,” etc. all work).
- The skill will push back on unrealistic scope or contradictions once, with a recommended fix. You decide.
- For small efforts it automatically uses lite mode (less structure, same approval rules).
- When you want a clean hand-off, ask for the package; it will confirm what to include before building the bundle.
